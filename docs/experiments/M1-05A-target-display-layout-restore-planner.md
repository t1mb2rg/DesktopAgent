# M1-05A：指定显示器布局恢复规划器

## 阶段目标

在 M1-03A（快照持久化）和 M1-04A（单图标移动后端）基础上，实现指定显示器布局恢复的纯逻辑规划器。M1-05A 只生成计划，不执行计划。

## 为什么批量恢复前必须先生成计划

批量图标恢复涉及多个图标的移动、依赖关系和冲突检测。直接执行可能导致图标互相阻塞、部分移动后无法完成后续移动。生成计划相当于一个可在执行前完全审计的「试运行」，允许在不动桌面图标的情况下验证所有逻辑边界。

## 为什么 M1 仅恢复指定显示器

M1 的恢复目标是逐步、可验证的。整桌面恢复涉及跨显示器搬迁、负坐标处理、未知 StableId 边界等复杂问题。M1-05A 将范围限制在单显示器，降低首次验证的复杂度。

## StableId 唯一匹配

所有 StableId 比较使用 `StringComparison.Ordinal`。快照目标集合内 StableId 必须唯一，当前桌面中每个 StableId 也必须恰好匹配一次。0 个匹配 → 缺失，>1 个匹配 → 阻断。

## 缺失图标处理

快照中在当前桌面已删除的图标标记为 `MissingFromCurrent`。计划持续可用，但 `HasBlockingErrors` 可能为 false（仅缺失不算阻断，除非缺失导致目标位置被占用）。

## 静态占用阻断

目标位置被非计划图标（不在恢复集合中）或已就位（`AlreadyAtTarget`）的图标占用时，标记为 `BlockedByStationaryIcon`，整体计划阻断。不自动移动这些额外图标。

## 移动依赖

目标位置被另一个 `MoveRequired` 图标占用时，建立有向依赖：「占用者必须先移动」。依赖通过拓扑排序确定执行顺序，不含环时生成 `MoveExecutionOrder`。

## 依赖环和临时中转需求

当 A 在位置 1 目标位置 2、B 在位置 2 目标位置 1 时，形成环。计划标记 `RequiresTemporaryStaging == true`，输出环中所有 StableId，不伪造直接执行顺序。M1-05B 将实现临时中转位置。

## 本阶段不调用 Writer

M1-05A 的所有代码均不包含 `IDesktopIconPositionWriter`、`SelectAndPositionItems` 或任何 Shell COM 操作。计划仅包含纯数据。

## 本阶段不寻找临时空位

`RequiresTemporaryStaging` 和环标识是给 M1-05B 的信号，本阶段不尝试在 Planner 中寻找或分配临时空位。

## M1-05B 将负责安全执行

- 使用本阶段的计划执行安全移动序列
- 遇到静态阻断或环时回滚或终止
- 实现临时中转位置分配与执行
