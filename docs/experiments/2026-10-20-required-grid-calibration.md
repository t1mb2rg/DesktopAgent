# 强制网格校准：第一阶段实现记录

日期：2026-10-20。对应 `2026-10-20-ai-centered-workspace-plan.md` 第一阶段，尚未提交。

## 用户试用反馈：校准结果应跨启动复用

用户明确要求：首次使用，以及更改桌面布置后才需要弹出网格校准；其他时候使用已保存的网格数据，不应每次启动都要求重新运行校准。最初仅记录，用户随后授权实施。

- 普通退出、重新启动应用本身不构成网格失效理由。有匹配当前环境的有效实测记录时，应直接复用并进入主界面。
- 启动时读取、核验已保存数据，与要求用户重新运行物理校准是两种操作；前者不应变成每次启动的交互阻断。
- 首次没有有效实测记录，或桌面布置发生影响网格有效性的变化后，仍要求完成校准；不以推断网格替代实测。
- “桌面布置变化”的具体判定范围待实施前细化：分辨率、缩放、屏幕排列、图标间距等几何环境变化，与普通分区草稿编辑、图标内容变化需分别判断，不能笼统全部作废。
- 后续验收至少覆盖：首次要求校准；成功后重启直接复用；相关环境变化后重新要求校准；新校准成功后再次重启仍可复用。

本轮调整：Explorer 重启通知只触发 fresh 核验，不再无条件作废记录；暂时无法计算环境身份时不覆盖上次持久化身份，当前不完整观测仍无法通过校准。新增“已有实测 → 重启复用 → DPI 变化阻断 → 新实测 → 再次重启复用”行为测试。真机新构建启动已直接进入 AI 助手，无需重跑物理校准。此前试用重复要求校准的完整原因没有逐一复现，不宣称覆盖所有环境变化。

## 已实现

- 产品启动显示独立校准页；主导航禁用。全部当前显示器的拓扑匹配实测网格通过几何校验后才放行，不使用 FirstRunCompleted、推断网格或自动执行授权代替校准。
- 统一 Application 校准判定和受保护观测源。AI 精确设计、旧单屏预览与保存设计复用需要校准；Workspace 产品执行使用受保护观测源，每次 dynamic capture 都重新核验。Direct Apply 产品 preflight 也使用受保护观测；原有执行内 fresh replan、ScopeGate 与恢复检查保留。
- 环境身份复用现有拓扑指纹，包含分辨率/显示边界、工作区、DPI、屏幕排列、主屏、图标间距和自动排列。显示/设置/DPI 与 Explorer TaskbarCreated 消息触发重新核验，只有已确认环境变化或用户主动重校准才作废记录。恢复前台和前台 30 秒兜底核验；隐藏到托盘后停止周期核验，原生变化通知仍可处理。
- 已观察到的环境切换与主动重校准记录失效时间水位，存入渠道数据目录的 `grid-calibration-environment.json`。重启或切回旧设置不能复活水位之前的实测记录。损坏记录保守要求新校准，存储故障不放行。
- 校准复用现有物理探针与明确确认。主动重校准前作废旧事实；失败、停止或部分完成不能靠旧事实通过。提供停止并清理、重试和退出。
- 校准前检查旧/Workspace/Dynamic 未解决恢复现场，禁止并发启动探针；引导页保留已有恢复检查入口，不开放日常编辑。执行期间不让 UI 生命周期取消穿过 Writer 边界；运行中的探针不会被深度驻留释放，退出需等待操作结束。
- 失效时取消当前 AI 请求、关闭编辑窗口/线框、清除精确预览与一次性入口，保留模板等持久化资产。

- Release 全解决方案及独立 PackagingTest Debug 构建通过。
- Computer Use 真机界面检查：三屏无实测时停留校准页；ShellNavigation 与菜单项均 disabled；打开说明后“开始校准”默认 disabled；取消后仍阻断主界面。测试未启动物理探针、未改显示设置、未移动真实图标。
