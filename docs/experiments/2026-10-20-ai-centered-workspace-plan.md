# AI 为中心的工作区交互改造方案

状态：源码核对后的实施方案，尚未实施。日期：2026-10-20。

## 已确定的产品要求

- 保留 WinUI 3 与现有执行、验证、日志和恢复链；主入口改为持续对话。
- 启用并配置 AI 后，校准通过即后台理解桌面，无需手动点击分析。未配置 AI 时提供设置入口，不偷偷启用 Provider。
- 首次使用必须校准；所有当前连接的桌面显示器必须具有有效实测网格。未满足时停留在引导，允许配置、重试、查看报告、退出，不进入日常主界面。
- 影响网格的环境变化后重新校准；没有推断网格或跳过校准的产品路径。
- 用户试用补充：有效实测网格须持久化并跨启动复用，普通启动不要求重跑校准；仅首次使用或桌面布置变化使网格失效时弹出校准。后续已授权实施，具体判定与验收见 `2026-10-20-required-grid-calibration.md`。
- 主界面以最新确认方案为准：左侧导航、聊天区与右侧设计画布；理解完成后自动展开画布，可收起重开，窄窗口上下排列；底部模型与输入区附近显示 AI 提出的操作卡片。实现记录见 `2026-10-20-startup-and-design-pane.md`。
- 自然语言与拓扑编辑共同修改同一份设计。分区支持移动、缩放、跨屏拖动，立即修改草稿，吸附到真实网格。
- 示例图标在对应网格单元中央显示；这属于渲染投影，不改变 Writer 的原生坐标定义。
- AI 按语境提出保存布局、打开精确预览等卡片。用户点击后本地执行，应用真实桌面保留最终确认。
- 拓扑收起到输入区附近及自动展开后做；首版保持可见。单个图标拖放不在本轮范围。

## 架构与状态归属

应用层持有 WorkspaceSession，View 仅订阅和提交动作。建议新名称在实施时按现有命名规范调整。

```text
启动 / 恢复前台 / 环境变化
        ↓
CalibrationReadinessService → Required / Running / Ready / Invalidated / Failed
        ↓ Ready
DesktopUnderstandingCoordinator → 缓存核对 / 差异分析 / 首次完整理解
        ↓
WorkspaceSession：理解 + 当前设计草稿 + Revision + 对话 + 操作卡片 + 撤销历史
        ↑                         ↑
   对话语义修改              拓扑拖动与缩放
        ↓                         ↓
         统一命令验证与状态归并
                    ↓
         保存卡片 / 精确预览卡片
                    ↓ 用户点击
         fresh observation + 当前设计编译 + 等价检查
                    ↓
         Frozen Preview → 明确确认 → 现有 Apply / Recovery
```

单一设计源采用可不完整的 `WorkspaceDesignDraft`，通过明确验证转换为完整 Blueprint；不要强迫每句讨论产生可编译 Blueprint。固定分区键在重命名和跨屏移动后保留。物理网格只在本地解释，不发给模型充当坐标 authority。

普通回复可以只有自然语言，设计变化通过小范围类型化命令表达，如新增分区、修改分区相对范围、改名、迁移显示器和修改类别归属。不要每轮重新输出完整 Blueprint。Provider 首选文本流与结构化工具动作；兼容性能力独立检测，不支持工具动作时使用小型响应信封，不退回整份设计输出。半截结构化参数不能修改状态或生成可点击卡片。

模型请求绑定 BaseRevision。用户等待回复时仍可拖动；旧回复不能覆盖较新的手动修改。首版对过期设计命令整体拒绝并以当前状态重试或请模型重新考虑，不做静默合并。卡片同样绑定设计版本和会话，有 Pending / Running / Succeeded / Failed / Stale 状态，重复点击不能重复写入。

模型只提出操作，不能自行执行。保存成功、预览成功和应用成功只能由本地结果确认。取消、断网、错误 JSON 保留已有草稿；自然语言里声称已完成不构成本地成功状态。

## 强制校准

以 fresh observation + 当前拓扑身份 + 各屏 Measured 实测覆盖 + 可信恢复/清理结果判定 Ready，不使用 `FirstRunCompleted` 或无人值守授权代替校准状态。校准事实与“记住此屏可自动执行”的权限保持分离，校准成功不授予自动移动权。

启动先验证已有事实，匹配时不重复做物理校准；缺失、失效或验证不可用则停在校准页。Partial 只展示逐屏结果，不能放行。无空位、探针失败、恢复或临时文件清理无法确认时给出实际原因，不以推断补齐。运行物理探针仍需现有明确确认。

监听显示设置等变化，并在恢复前台、打开编辑、生成预览、保存几何设计及每次写入前重新核验。事件通知只是唤醒信号，fresh 核验才是事实。无法可靠读取时按不可用处理。

一旦变化，阻止新设计编辑和新执行，作废精确预览、未确认卡片及执行凭据，保留对话与语义设计。相对设计需在新环境重新确认/吸附，不重放旧像素。校准事实需与当前环境一致；不能在变化后仅凭 `Ready=true` 放行。

执行中环境变化由现有 fail-closed 与恢复协议接管：停止后续不安全写入，不在已发生副作用时直接中断进程或并发启动探针。校准必须等待执行/恢复互斥锁释放；必要恢复不被引导页隐藏或永久阻断。

原生探针与恢复是校准门本身的受限维护路径，不能被“未校准禁止写入”锁死；除此之外所有产品移动入口须通过新门槛。Diagnostics 可以保留工程推断观测，但不能借此进入产品执行。

## 真实网格编辑与渲染

共用坐标投影及吸附服务，供聊天拓扑、布局管理画布和桌面分区编辑器调用。区分画布 DIP、全局物理像素、显示器本地坐标、设计相对矩形，覆盖负坐标和混合 DPI。

真实 slot 是原生锚点，分区边界需按已实测锚点与间距推导单元边界，不把锚点误当矩形左上角。实施前以探针/实机核对单元中心的定义，避免给 Writer 坐标统一加半格。实际观察位置与示例中心点的显示必须区分。

移动使用已校准网格的整数步长；缩放吸附边缘，最小一个有效单元；跨屏切换到目标屏的网格和间距，按目标屏重新吸附，边缘限制在有效工作区。首版保持矩形、阻止分区重叠，容量不足给出可见诊断，不偷偷移动其他分区或图标。跨屏后需要重新确认的空间关系明确标记，不静默丢弃约束。

拖动即时本地渲染，松手提交一次设计修订并加入撤销历史，不逐帧调用 AI。Escape 取消当前手势；指针捕获丢失按明确取消规则处理。手动提交会使旧 Frozen Preview 和旧卡片失效。AI 以后读取最新草稿及紧凑修改摘要。

## 实施顺序与验收

| 阶段 | 具体交付 | 必须通过的场景 |
| --- | --- | --- |
| 1 校准基础 | 从 View 提取校准协调；统一 Ready 判定；启动硬引导与产品底层门槛；更新旧可选校准合同 | 首次/部分/失败不放行；有效缓存可进入；分辨率、DPI、拓扑、间距变化失效；失效不能写；探针取消清理；恢复路径不死锁。 |
| 2 会话与设计状态 | 独立 WorkspaceSession、设计命令、修订和撤销；持久化草稿/会话，不保存执行权 | 聊天与手动修改同源；过期响应不覆盖拖动；撤销按修订生效；跨重启草稿可恢复但预览票据不可恢复。 |
| 3 对话主界面 | 按草图实现聊天、顶部拓扑、模型输入、自动理解协调和回复流；停止要求每轮完整设计 | 校准成功后自动理解；打开/隐藏页面不重复任务；纯聊天无设计变化；断网可取消重试；缓存无需强制全量重分析；配置缺失给出可操作状态。 |
| 4 分区交互 | 共用投影/网格吸附；三种分区调整；示例居中；两处编辑器接入 | 负坐标、混合 DPI、跨屏间距不同；缩放最小尺寸；手动修改 AI 可见；只改设计不移动图标；不以视觉偏移修改执行坐标。 |
| 5 卡片与精确设计 | 保存与精确预览类型化卡片；编译当前设计；衔接原精确审阅及确认 | AI 提出、用户点击、本地回报；保存不等于应用；重复点击不重入；版本变化卡片失效；精确生成不重设计；Apply fresh check 与恢复回归。 |
| 6 候选版验收 | 同一候选构建走完整真机流程，更新产品文档与发布清单 | 从首次校准到聊天/拖动/保存/复用/预览/应用/撤销完整跑通；显示设置变化、Explorer 重启、Provider 错误、窄窗口和长期驻留。 |

测试重点为状态转换、修订并发、坐标投影、门槛覆盖及副作用边界，不用仅检查文案的测试替代行为测试。每阶段执行相关测试并构建，最终跑全量及真机验收。

本方案不添加依赖于当前模型供应商的服务，不更换 AI 模型，不自动执行物理探针，不修改系统显示设置。实施阶段先验证现有网格实测是否足以定义统一单元边界；若观测字段不足，补齐测量事实，不能以估算满足强制校准。
