# 对话操作入口与实际卡片状态

日期：2026-10-20，尚未提交。用户指出上一轮模型说“下面有保存卡片”，实际没有出现；反馈后下一轮才出现“一轮只能提出一张操作卡片”。这两个现象不能混为一个根因。

## 证据边界

原程序没有保存该轮原始工具返回，不能事后确认前一轮是模型只输出文字，还是 UI 状态未保留。已核对：普通文字不会生成卡片；第二个 offer_action 会拒绝整轮；发送新消息一开始就清除旧卡片，即使新请求失败也无法恢复。没有证据将第一轮缺失完全归因于单卡限制。

## 改动

- Provider 返回有界操作列表，保存与预览可以同时提出；同种同名建议去重，冲突保存名称拒绝，未知工具和参数仍拒绝整轮。旧 Action 属性兼容已有消费者。
- UI 分别显示本地实际收到的建议。点击某项成功后只移除该项，其他项保留。版本变化仍使旧建议失效，忙碌时禁用操作。
- 新请求开始不再主动清除旧建议；失败或普通无修改回复不会仅因开始新请求而吞掉卡片。
- 有分区草稿时提供固定“保存当前设计”和“检查精确预览”入口，直接复用现有产品服务，不依赖模型是否调用 offer_action，不自动执行。
- 一轮完成后明确显示实际生成数量；没有工具动作时显示“本轮没有生成操作卡片”及固定入口说明，不把模型文字当作卡片存在的事实。
- 提示词明确要求真正调用工具才能声明提出卡片。没有用关键词匹配自动保存或执行。
