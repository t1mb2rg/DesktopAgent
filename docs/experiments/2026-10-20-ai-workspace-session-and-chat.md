## 已落地的行为

- 产品窗口持有 WorkspaceSession，AI View 与布局工作台共用它。页面释放不释放草稿或累计设计偏好；同一进程中已理解的语义模型也不再由 View 私有字段独占。
- 核心草稿允许缺少分区或暂时存在未解决引用。保存会话不要求可执行；转换为 Blueprint、保存正式布局或精确编译时仍要求完整有效。
- 增量设计命令成批原子提交，使用 BaseRevision 检查。撤销、重做与语义上下文刷新都推进修订；旧 AI 响应不能因为撤销而重新获得覆盖权。
- 会话保存草稿、累计语义意图、最多 50 步撤销/重做历史和 200 条聊天记录。显式 DTO 白名单不接收 Frozen Preview、票据或 Writer payload；未知字段、损坏文件、版本冲突保守拒绝，保留原记录。旧保存任务不能覆盖更新的序列。
- 渠道目录增加 `workspace-session.json`。保存队列独立于页面；退出先取消后台理解，再等待保存队列。保存失败在界面明确显示，不假装已保存。
- 校准通过后进入 AI 页面，后台核对持久化纯语义理解。来源仍 Current 时适配为对话上下文，不重新请求分类、不恢复分区或执行权；需要重新理解时调用既有理解服务。隐藏/切页不取消后台理解，校准失效与退出会取消。
- AI 页面按用户草图调整为顶部拓扑、中间聊天、底部输入与模型设置入口，提供停止、撤销、重做。流式文字逐段显示，不再强制普通回复输出完整 JSON。
- 新 Chat Provider 使用可选 `edit_design` 与 `offer_action` 工具。前者仅提交相关分区、摘要或分类映射变更；后者提出保存布局/检查精确预览卡片。动作只在完整响应结束、参数与版本校验通过后进入本地状态。
- 首版支持普通文本流与工具调用流，也能处理服务端返回普通 JSON completion 的兼容情况。不支持工具调用的服务端会给出错误，不静默回退到整份 Blueprint 重生成。
- 卡片需要用户点击；可选择“暂不”。卡片绑定当前设计修订，修改或撤销后旧卡片失效。保存卡片写入正式布局库并以本地实际版本回报；预览卡片直接 fresh 读取、校准检查、编译和独立验算当前草稿，再打开原精确设计面，不调用模型重设计。
- 工作区应用票据同时绑定设计修订，确认对话框关闭后再次核验，避免确认期间的后台更新继续应用旧设计。已有 Direct Apply 也在确认返回后核对设计版本及预览对象。

## 试用修复：流式响应长度误判

用户试用中提交“我想所有图标都放左侧副屏”后很快收到响应超长错误。本地测试复现了一个相关缺陷：旧实现将逐片重复的 SSE JSON 信封全部累计到 512 Ki 字符上限，8000 字的碎片响应即可失败，不能据此认为模型生成了过长正文。现在正文和工具名称/参数共用原 512 Ki 字符预算，传输另设 16 Mi 字符预算，注释等忽略行也计入传输量；单个 SSE 事件原有上限保留。新增碎片响应、正文超限、工具参数超限及注释传输超限测试。此为离线复现与修复，真实 Provider 同句重试仍待用户验证。

## 明确尚未完成

1. 顶部拓扑当前只展示设计；分区移动、缩放、跨屏拖动、与旧编辑器共用真实网格吸附、示例点中心投影属于下一阶段。
2. 桌面理解能复用来源未变化的分类；来源变化时目前仍走完整理解，尚未实现仅分类新增/变化项目。
3. 工具首版支持分区、摘要和分类映射；显示器 Preserve 策略、空间关系和项目例外的完整对话编辑还需扩展。带历史 ItemOverride 的草稿在新卡片预览入口会要求回设计库重新确认绑定，不能猜测。
4. 卡片及预览执行权不跨重启恢复。当前模型通过设置页配置；底部提供入口，尚未提供多模型快捷下拉选择。
5. 聊天首版显示可选择的普通文本，Markdown 富排版与顶部窗格折叠后做。
6. 新版仍需真实完成全部显示器校准后验证 UI 与完整对话/保存/预览流程。没有为视觉检查添加绕过校准的入口。

旧结构化理解与 legacy 设计代码暂时保留用于既有合同和诊断路径；日常聊天发送已经使用新 Provider，精确预览卡片使用当前草稿编译链。后续整理遗留代码时应按实际调用关系删除，不能仅删掉仍有消费者的安全合同。
