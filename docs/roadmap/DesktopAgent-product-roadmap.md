## 1. 文档目的

本文档用于冻结 DesktopAgent 的产品边界、技术主线、安全原则、里程碑目标和关键决策门，避免后续开发过程中反复改变 M2、M3、M4 等阶段的含义。

本文档不是不可修改的详细施工表。它遵循以下规则：

- 产品定位、版本边界、安全不变量和里程碑验收目标在人工确认后冻结；
- 类名、文件结构、PR 数量、具体 Windows API、模型提供方和安装工具可以根据开发结果调整；
- 阶段内部实现允许优化，但不得绕过已经冻结的安全链路；
- 每个里程碑收尾时更新实际状态、验收结果和后续决策；
- 路线发生实质变更时，应通过独立文档 PR 修改本文档并记录原因。

## 3. 产品定位

### 3.1 v1.0 定位

DesktopAgent v1.0 是一个面向 Windows 11 的本地桌面图标智能布局与自动整理工具。

它直接作用于 Explorer 原生桌面图标布局，不创建覆盖桌面的替代层，也不接管 Explorer 的正常交互。

v1.0 可以：

- 读取多显示器拓扑和桌面图标物理坐标；
- 创建布局模板和可视 Zone；
- 使用确定性规则分配图标；
- 生成布局预览、差异说明和安全执行候选；
- 在用户确认或明确自动授权后移动 Explorer 图标；
- 保存安全快照、验证结果并在失败时回滚或进入恢复流程；
- 常驻后台，提供建议模式和受控无人值守自动模式；
- 使用本地规则和可选 AI 提供分类及自然语言规则建议。

v1.0 不会：

- 移动真实文件到其他目录；
- 重命名、删除或归档真实文件；
- 扫描或管理整个磁盘；
- 让 AI 直接调用 Shell Writer；
- 以自绘桌面或覆盖层替代 Explorer 原生桌面。

### 3.2 v2.0 方向

真实文件分类、移动、归档和跨重启事务恢复属于 v2.0 探索方向。

真实文件路径变化会引入覆盖冲突、跨卷复制、权限、云盘占位文件、文件占用、重解析点、事务日志和数据恢复等新的风险模型，因此不作为 v1.x 的普通增量功能。

## 4. 冻结技术路线

### 4.1 平台与技术栈

- Windows 11 x64；
- .NET 10；
- WPF 作为 M0–M4 的当前界面框架；
- Windows Shell COM 与必要的 Win32 API；
- SQLite 本地持久化；
- xUnit 自动化测试；
- GitHub Actions 持续集成；
- GPL-3.0-or-later；
- GitHub Releases 与项目网站作为主要发布渠道；
- Microsoft Store 暂不作为首要发布渠道。

### 4.2 分层约束

```text
DesktopAgent.Core
├─ 领域模型
├─ 模板、Zone、规则与分类
├─ 确定性布局规划
├─ RestorePlan / ExecutionPlan
├─ 自动化策略与安全门禁
└─ 不依赖 WPF、WinUI、Shell COM 或 SQLite

DesktopAgent.WindowsInterop
├─ Win32 显示器拓扑
├─ Shell 桌面读取
├─ Shell 图标 Writer
├─ Explorer / Windows 事件适配
└─ 安全执行协调器

DesktopAgent.Persistence
├─ SQLite Store
├─ Schema 迁移
├─ 配置、历史与恢复会话
└─ 不承载布局算法

DesktopAgent.Poc / 后续正式 UI
├─ WPF 当前表现层
├─ 用户交互、预览和确认
├─ 托盘、通知与设置
└─ 不直接实现核心规划算法
```

必须长期保持：

- Core 不引用 WPF、WinUI 3、Shell COM 或 SQLite 类型；
- UI 不直接调用 Writer；
- AI 不输出物理坐标，也不直接调用 Writer；
- Shell COM 和 Win32 只在 WindowsInterop 中集中封装；
- 持久化层只实现存储接口和数据迁移；
- 所有真实写入都必须经过正式计划和安全协调器。

### 4.3 多显示器原则

- 从底层支持任意数量显示器；
- 支持虚拟桌面负 X / 负 Y 物理坐标；
- 每次布局操作解析一个明确目标显示器；
- 非目标显示器图标保持 OutOfScope，不被计划改写；
- 安全快照覆盖完整桌面，而不是只保存目标显示器；
- 显示器拓扑、工作区、DPI 或目标引用变化时拒绝执行陈旧计划。

## 5. 冻结的核心安全链路

```text
显示器拓扑与能力读取
→ 桌面图标完整读取
→ 显示器归属
→ 当前布局快照
→ 模板、Zone 与规则解析
→ 确定性槽位和坐标规划
→ 布局预览
→ 目标布局快照
→ RestorePlan
→ ExecutionPlan
→ 执行候选与风险说明
→ 用户确认或自动化授权门禁
→ 执行前重新读取、重新分配、重新规划
→ 保存并回读验证安全快照
→ Writer 逐步执行
→ 独立重新读取验证
→ 完成、回滚或进入人工恢复
```

任何新功能不得绕过以下不变量：

1. 读取不完整时禁止保存正式执行候选或进行写入；
2. StableId 和 DeviceName 使用 Ordinal 精确匹配；
3. 自动排列开启时拒绝写入；
4. 不缓存旧 PIDL，Writer 每次重新枚举并唯一匹配；
5. 真实执行前必须重新读取并重新规划；
6. Writer 前必须保存并回读验证完整安全快照；
7. Writer 异常视为可能已产生副作用；
8. 身份或前置位置不可信时禁止盲目回滚；
9. 位置不确定或回滚不完整时熔断后续自动写入；
10. 独立读回验证是完成状态的一部分；
11. 宁可停止整理，也不冒险继续执行。

### 9.2 当前已完成能力

截至 2026-08-04，M2 已完成：

- 模板和 Zone 领域模型；
- SQLite 模板持久化；
- 目标显示器解析；
- Zone 容量、槽位和确定性分配；

- PreviewPlan 到 TargetSnapshot、RestorePlan、ExecutionPlan 和安全执行候选的纯 Core 转换；
- 无依赖、依赖链、循环和临时中转计划的复用能力。

### 9.3 剩余主线

- 执行前完整重读与重规划；

M2-04C：完成完整安全能力，包括：

- 位置不确定与回滚不完整的人工处理锁；

### 9.4 M2 完成标准

```text
选择或创建模板
```

必须覆盖：

- 无依赖批量移动；
- 有向无环依赖链；
- 循环和临时中转；
- 应用重启后的持久化恢复。

M2 不包括后台无人值守执行和 AI 分类。

## 10. M3：后台感知与无人值守自动整理

状态：已冻结。

### 10.1 阶段目标

让 DesktopAgent 常驻后台，在用户授权的边界内感知桌面变化，生成最新整理候选，并在安全门禁通过时无人值守完成 M2 的完整执行闭环。

### 10.2 运行模式

| 模式 | 行为 |
|---|---|
| 手动 | 用户主动打开应用并发起整理 |
| 建议 | 后台检测变化并生成候选，用户确认后执行 |
| 自动 | 满足用户授权和安全门禁时无人值守执行，否则退回建议模式 |

默认模式为建议模式。自动模式必须由用户显式开启。

### 10.3 自动化链路

```text
文件系统或 Windows 事件提示变化
→ 防抖并等待桌面稳定
→ Shell Reader 完整重读
→ 状态 Diff
→ 自动选择模板和规则
→ 生成最新执行候选
→ 自动化权限与风险门禁
→ 安全快照
→ 批量执行
→ 独立验证
→ 历史记录与通知
```

变化监听只作为触发提示，最终状态必须以 Shell Reader 完整重读为准。

### 10.4 M3 核心能力

- 托盘常驻；
- 桌面变化监听与防抖；
- 状态稳定检测；
- 手动、建议和自动三种模式；
- 自动执行范围、最大移动数量和暂停条件；
- 内部变化识别，防止程序移动后无限重复触发；
- 最短执行间隔、冷却期和单位时间次数上限；
- 连续失败熔断；
- 自动整理历史和结果通知；
- 开机启动；
- 高风险计划自动退回建议模式。

### 10.5 无人值守安全门禁

自动执行至少要求：

- 当前读取完整；
- 显示器拓扑和 IconSpacing 稳定；
- 模板与规则有效；
- 不存在 Unassigned 或阻断项；
- 自动排列关闭；
- 不存在未完成或位置不确定的恢复会话；
- 移动数量和步骤数量不超过用户上限；
- 执行前重读后生成的候选仍符合授权策略；
- 安全快照保存与回读成功；
- 程序未处于熔断或暂停状态。

任何条件不满足时，禁止强行写入，并退回建议模式或人工恢复。

### 10.6 M3 完成标准

- 应用随 Windows 启动并进入托盘；
- 用户启用自动模式并绑定模板；
- 新增桌面项目后自动检测、重读和生成计划；
- 安全门禁通过时无需点击即可完成整理；
- 完成后生成历史和通知；
- 失败时自动回滚；
- 回滚不完整或位置不确定时立即熔断自动模式并禁止继续写入。

## 11. M4：智能分类与自然语言规则

状态：已冻结。

### 11.1 阶段目标

让 DesktopAgent 理解桌面项目应当如何分类，自动推荐 Zone 和长期规则，并允许用户通过自然语言创建结构化整理规则。

### 11.2 三层决策顺序

1. 用户明确规则；
2. 本地确定性通用规则；
3. 可选 AI 语义建议。

高优先级规则永远覆盖低优先级建议。AI 不可用时，M2 和 M3 必须继续完整工作。

### 11.3 M4-01：通用规则与行为学习

- StableId 精确规则；
- 扩展名规则；
- 文件名模式规则；
- ItemKind 规则；
- 快捷方式目标规则；
- 有限组合条件、优先级和冲突诊断；
- 规则命中测试；
- 从用户重复确认行为生成长期规则建议；
- SQLite 持久化与规则编辑 UI。

### 11.4 M4-02：AI 分类与自然语言规则

- 模型提供方抽象；
- 结构化分类响应；
- Zone、规则和置信度校验；
- 自然语言生成 RuleDraft；
- 保存前展示解析结果并由用户确认；
- 高置信度建议可进入用户授权的自动模式；
- 中低置信度建议退回人工确认；
- 模型不可用时降级到本地规则。

### 11.5 AI 安全与隐私边界

- AI 不直接调用 Writer；
- AI 不直接输出物理坐标；
- AI 输出必须转换为受约束的结构化规则或分类建议；
- 默认不读取或上传文件正文；
- 默认不上传文件本身；
- 明确展示会发送给模型的字段；
- API 密钥不得写入普通日志；
- 用户可以完全关闭 AI；
- 所有 AI 结果必须经过本地结构校验、冲突检查、Planner 和 M3 安全门禁。

## 12. M5-00：WinUI 3 技术验证与决策门

状态：决策门。

### 12.1 时间点

M0–M4 继续使用 WPF。M4 核心能力完成、M5 正式产品 UI 全面实施之前，进行一次隔离的 WinUI 3 可行性验证。

### 12.2 验证方式

新建独立 WinUI 3 壳项目，不直接重写现有 WPF 项目，验证一条代表性只读链路：

```text
启动应用
→ 读取显示器和模板
→ 打开模板/规则页面
→ 生成布局预览
→ 显示执行候选
```

验证重点：

- 对现有 Core、Persistence 和 WindowsInterop 的引用；
- Shell COM 与 STA 执行模型；
- Canvas 预览与缩放；
- 表格/规则编辑控件；
- 多窗口、对话框和窗口句柄；
- 托盘、通知、单实例和开机启动；
- SQLite；
- 打包与未打包部署；
- GitHub Actions；
- 启动时间、内存和空闲 CPU。

### 12.3 决策结果

- 验证通过：v1.0 正式 UI 优先采用 WinUI 3；
- 验证存在明显阻断：v1.0 继续使用 WPF，WinUI 3 迁移顺延到后续独立阶段。

WinUI 3 迁移和真实文件整理不得在同一个不可拆分阶段中同时推进。

## 13. M5：正式产品化与 v1.0 发布

状态：方向已冻结。

### 13.1 阶段目标

将 M1–M4 的能力从 PoC 收敛为可安装、可配置、可诊断、可升级并可长期运行的 Windows 桌面产品。

### 13.2 正式产品界面

正式 UI 至少包括：

- 首页与当前桌面状态；
- 一键整理和执行结果；
- 模板、Zone、规则和预览；
- 手动、建议和自动模式设置；
- 自动化权限、暂停条件和熔断状态；
- 分类规则、AI 设置和自然语言规则；
- 执行历史、安全快照、撤销和恢复会话；
- 显示器、通知、隐私、日志和关于设置。

### 13.3 安装、升级与数据兼容

- 标准 Windows x64 安装包；
- 便携版；
- 正确安装、覆盖升级和卸载；
- 可选开机启动；
- SQLite Schema 只允许向前迁移；
- 升级前备份数据库；
- 迁移失败时禁止启动 Writer；
- 模板、规则、历史和恢复会话不得被静默破坏；
- 提供配置和数据导入、导出或备份能力。

### 13.4 性能与诊断

- 冷启动时间；
- 托盘常驻内存；
- 空闲 CPU；
- Shell Reader 调用频率；
- 防抖和后台队列；
- SQLite 生命周期；
- WPF/WinUI 窗口关闭后的资源释放；
- 日志滚动；
- AI 超时和降级；
- Explorer 重启恢复；
- 一键复制和打包脱敏诊断信息。

发布内容至少包括：

- 安装版；

- SHA-256 校验文件；

## 17. 开发与合并流程

1. 一个用户可见闭环或明确阶段使用一个功能分支；
2. 实现、测试、修复和全量复测在同一分支完成；
3. 创建 Draft PR；
4. 独立核对远端真实 diff、范围和 GitHub Actions；
5. 只因构建/测试失败、核心功能缺失、状态损坏、Writer/快照/恢复安全问题或不可恢复实机风险阻止合并；
6. 可选 UI 打磨、命名偏好、重复测试和次要文档措辞不长期阻塞主线；
7. 最多进行一轮集中修复；
8. 通过后 Squash Merge；
9. 同步 main、删除旧分支并立即进入下一阶段。

Claude 或其他实现代理不得：

- 在 main 上直接开发；
- 自行合并 PR；
- force-push 或 rebase 共享分支；
- 在阶段范围外接入 Writer；
- 未经明确门禁移动真实桌面图标；
- 执行破坏性文件操作。

## 18. 路线变更规则

以下变更必须人工确认并修改本文档：

- PR 拆分数量；
- 具体监听 API；
- 具体模型和服务提供商；
- UI 控件选型；
- 安装工具；
- 不改变外部语义的性能实现。
