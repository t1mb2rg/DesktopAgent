# Tessel v1 产品收口基线（2026-10-15）

状态：**进行中，不等于发布就绪**。基于 `agent/grid-measurement-fact-v1`（#108）；第一批 UI 修正为 #109。本文是验收清单，不是扩大产品边界的授权。

## 0. 不变量

1. 所有真实桌面写入必须走已有 Coordinator / ScopeGate / Recovery checkpoint / independent verification；WinUI 不直接拿 Shell Writer。
2. 网格实测证据与逐屏站定授权是两种不同事实；拓扑改变时不得复用旧授权。
3. AI 设计与 Blueprint 是意图资产，不能等价于可执行的一次性 Frozen Preview。任何旧设计再次执行都须 fresh observation → compile → preview → 明确确认。
4. 拒绝一次写入不得悄悄变成重新规划的写入；回滚只按可信检查点，不猜。
5. `main` 不承接未经 CI 与真机验证的大规模 stacked 改动；不借收口重做 Core 模型。

## 3. 推荐收口顺序

1. **保护正确性**：F-3、P-1 的算法/生命周期设计裁决；先写失败与顺序敏感性测试，再改代码。P-1 的默认方向倾向稳定保留合法槽位，但要先证明不违反显式区内排序和 ZoneOverride。
2. **补 UI 生命周期**：F-2、F-4、F-5、F-1。已知状态只读显示不应持有写入权；设计库详情仍不得直接写桌面。
3. **补自动执行物理门**：A-1、C-1。保持预设低预算，不用调大 `MAX_MOVES` 伪造通过。
4. **最后发布收口**：R-1、G-1；逐项导出与安装验收，确认后再决定何时归并到 `main`。

## 4. 每个分片的完成条件

- **Functional Review**：提供输入、操作、预期与实际，失败案例包含可复现证据；新增回归断言且全量测试通过。
- **Architecture Review**：证明不新增第二条 Writer/Recovery 通道，不把 AI 意图提升为执行权限，不把读取/展示和写入权限混用。
- **Physical Gate**：凡改动 WinUI、Shell、自动执行、安装或恢复的，至少在实际 Windows 多屏环境完成对应交互与真机验收。
- **Delivery**：提交 SHA、CI run、真机证据、已知缺口与回滚办法必须能追溯；未达到的项保持未完成。
